# 灵答品牌与上游入口收敛

状态：implemented
类型：simplification
Owner：web/src/stores/info.js

## 问题

公开页面、能力发现和 CLI 同时出现 Yuxi、语析与灵答，用户会把同一个产品理解成多个系统。页面还主动请求 GitHub Stars，并在设置、上传和评估等产品流程中暴露上游推广入口，与当前部署的产品身份不一致。

## 决策

- 默认品牌、系统发现名称和新建 CLI Key 名称统一为“灵答”。
- Web 运行时把旧默认品牌文案归一化为“灵答”，固定产品 logo、头像、版权和版本展示；本部署不承诺旧白标字段继续覆盖这些产品身份字段。
- 移除首页、侧栏、用户菜单、设置、上传和评估弹窗中的 GitHub、开源推广、Stars 请求及上游帮助入口。
- skills.sh、ModelScope 和代码仓库安装地址属于功能性安装来源，不按推广入口删除。

## 替代方案

- 只修改模板默认值并完整保留部署者白标覆盖：兼容性最好，但运行数据库中的旧值仍会让页面混用品牌。
- 保留一个集中式“关于/帮助”入口：可保留源码归属和排障路径，但用户明确要求当前页面不再出现这些入口。
- 把仓库与文档地址改成部署配置：扩展性更强，但为本次明确的单品牌部署增加了不需要的配置面。

## 后果

用户在登录页、工作区、Agent、知识库、设置、上传和评估页面只看到“灵答”，浏览器也不再为 Stars 主动访问 GitHub。已有自定义白标部署如果依赖 logo、头像或版权覆盖，需要在复用本分支前重新确认兼容策略；源码许可证、包名和内部 `yuxi_*` 标识不属于本次页面品牌替换。
